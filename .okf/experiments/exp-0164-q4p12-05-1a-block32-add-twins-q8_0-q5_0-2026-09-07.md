# Result

G4P12-05-1a (commits `30835b4` Q8_0, `c9a5ff7` Q5_0) re-homes the block32 families' served generic/`_m2` `_add` twins onto `Metal_block_codegen` structural emission — the exact 04d-A2 pattern applied to the first non-Q4_0 families, retiring the llama-text patching for those twins.

1. **Block32 twin templates.** `emit_block32_linear_add` / `emit_block32_m2_add` mirror `emit_linear_pair`'s decode body byte-for-byte with the twin writeback tail: the additive tensor (the residual, bound to the flat `bias` buffer(2) slot) is applied element-wise via `half(half(acc) + bias[idx])` (double rounding — the legacy twin numerics contract), flat ABI (input buffer(0), weight buffer(1), bias buffer(2), output buffer(3), params buffer(4)), no `has_bias`/`bias_value` store block. The schema-value function (`llmopt_schema_q8_0_value`/`llmopt_schema_q5_0_value`) is in scope because `quant_source` emits the family value function + flats before the twin text.
2. **Schema-level admissions.** `q8_0_twin_schema_geometry`/`q5_0_twin_schema_geometry` validate the family's quant type/code bits/block-32 fields (offsets only prove physical-field presence — the value function reads the block directly); `q{8_0,5_0}_{linear,m2}_add_kernel` emit the twin for a caller-chosen kernel name. Exported from the .mli.
3. **Lower dispatch.** `Metal.lower`'s quant-add Result fold dispatches Q4_0/Q8_0/Q5_0 generic/`_m2` bases to the codegen twins before the shim; everything else keeps the shim unchanged. The Q4_0-only guard in the shim stays (Q8_0/Q5_0 never reach it for their served bases).
4. **Reachable-shape fact (probed).** The uniform costed catalog's x8/x4/m4/m16/m32 candidates exist only for families with parametric kernels, so Q8_0/Q5_0 Linear-add selection only ever names generic (any m≠2 shape) or `_m2` (m=2). Probes over m=1/2/4/16/22 × n=32/64/4096 all lower and serve through one of the two twins — there is no llama-zoo-missing crash surface for these families (unlike Q4_0's retired x8/x4 `Invalid_argument`). The Q8_0 program byte diff (before/after) showed plain Linear programs byte-identical (zoo untouched) and only the two `_add` twin bodies changed (llama `block_q8_0` decode → parametric schema-value decode, matching the flat Q8_0 siblings already serving plain decode).
5. **Pins.** `test/golden/q8_0_linear_f16_add.msl`, `q8_0_linear_f16_m2_add.msl`, `q5_0_linear_f16_add.msl`, `q5_0_linear_f16_m2_add.msl` hold the parametric emission oracle (lower-level byte-identity), structural checks assert the uchar weight, schema-value decode (`llmopt_schema_q{8_0,5_0}_value(row_blocks + block * `), double-rounding tails, and the absence of `block_q{8_0,5_0}`/`has_bias`/`bias_value`, plus a Q8_0 m=1 n=4096 lower proof serving the generic twin.
