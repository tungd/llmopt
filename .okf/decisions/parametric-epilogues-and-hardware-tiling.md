# Decision

`llmopt` rejects opaque external runtime engines (such as TVM or ArrayJit's in-process schedule runtime) for decode serving, preserving its **zero-overhead, prebaked Indirect Command Buffer (ICB) and specialized sub-byte dequantization kernels (350 GB/s)**.

Instead, `llmopt` internalizes the **two high-value compiler design patterns** proven by ArrayJit:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. Algebraic Epilogue Inlining (Eliminates 2,500 lines of AST matchers)     │
│                                                                             │
│  Linear / Norm Kernel ──► Parameterized Epilogue (Identity | Silu_mul |     │
│                           Gelu | Add_residual | Bias)                       │
│  Result: Fused activation writeback generated by construction.              │
├─────────────────────────────────────────────────────────────────────────────┤
│ 2. Hardware-Aware Prefill GEMM Tiling (Peak TFLOPS for M >> 1)             │
│                                                                             │
│  Prefill GEMM (FP16/BF16) ──► simdgroup_matrix (8x8x8)                     │
│                           ──► Swizzle_b128 XOR Threadgroup Bank Staging     │
│                           ──► Software Pipelining (Depth = 2)               │
├─────────────────────────────────────────────────────────────────────────────┤
│ 3. Multi-Backend Intrinsic Table (Zero-duplication Metal & ROCm HIP)        │
│                                                                             │
│  Unified Loop Template ──► Target Intrinsics Table (simd_sum vs __shfl_sync)│
│                        ──► Metal MSL / AMD HIP C++                          │
└─────────────────────────────────────────────────────────────────────────────┘
```

# Why We Rejected Direct ArrayJit Runtime Integration

A direct integration probe revealed severe **abstraction leakages**:
1. **Homogeneous Precision Coercion**: ArrayJit forces all binary expressions to output precision (`is_homogeneous_prec_binop`), causing invalid C/MSL syntax (`half % half`, `half & half`) when mixing sub-byte integer unpacking with half-precision arithmetic.
2. **Intermediate DRAM Spilling**: Working around this type leakage required materializing 14 intermediate tensors into GPU DRAM per layer, resulting in a **$10,000\times$ performance collapse (23.6 ms decode latency at 0.003 GB/s)**.
3. **Micro-Dispatch Overhead**: Executing schedule commands via individual `Context.routine` dispatches re-introduced the multi-hundred kernel driver dispatch bottleneck.

# Architectural Enhancements

### 1. Parametric Epilogue Inlining (`lib/epilogue.ml`)
Replaces `pass_fuse_rms_norm.ml`, `pass_fuse_swiglu_ffn.ml`, and `pass_fuse_linear_bias.ml`.
Each linear or reduction kernel accepts a first-class epilogue description:
```ocaml
type epilogue =
  | None
  | Bias of Tensor.t
  | Silu_mul of { up: Tensor.t }
  | Gelu
  | Residual_add of { residual: Tensor.t }
  | Rms_norm_scale of { weight: Tensor.t; eps: float }
```
The kernel emitter generates the epilogue arithmetic directly at the register writeback site without intermediate DRAM roundtrips or AST pattern queries.

### 2. High-Performance Prefill GEMM (`Tile_mma`)
Implements Apple Silicon `simdgroup_matrix` $8\times 8\times 8$ tile staging in `lib/metal.ml`:
- Shared threadgroup memory tiles with **XOR bank swizzling** to guarantee 0 bank conflicts across 32 SIMD lanes.
- 2-stage double buffering (software pipelining) overlapping asynchronous global-to-shared memory loads with ALU matrix math.

### 3. Abstract Target Syntax Interface
Refactors kernel generation to separate loop nest geometry from hardware-specific intrinsic names, preparing `llmopt` for native AMD ROCm (HIP) compilation.
