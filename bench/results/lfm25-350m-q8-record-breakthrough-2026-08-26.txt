# LFM2.5-350M Q8 Serving Record Breakthrough Receipt

Date: 2026-08-26
Host: Apple M4 Pro (macOS, 24 GB Unified Memory)
Target: LiquidAI/LFM2.5-350M, Q8 weight-only, opt-in token-id output

## 1. Problem Diagnosis & Root Causes Resolved

1. **Serving Queue Priority Inversion Under Concurrency:**
   - In `bin/lfm_serve.ml`, `Serving_queue.pop_next_batch` popped both decode and prefill requests.
   - The event loop unconditionally executed incoming monolithic prefills (60–100 ms) before active decodes.
   - When conversation 1 arrived while conversation 0 was decoding, conversation 0 experienced a 100+ ms pause, exploding TPOT to 60.2 ms.
   - **Fix:** Swapped priority in `bin/lfm_serve.ml` so active decodes execute first. If decodes are dispatched, prefill candidate is deferred until decode slots advance.

2. **Kernel Performance Bottleneck:**
   - In experimental macro-fusion branches, monolithic kernels attempted to evaluate reductions across wide column spaces with a single threadgroup, resulting in GPU underutilization.
   - Verified and served via the optimized SIMD-pair kernels (`llmopt_q8_gemv_pair_simd`, `llmopt_q8_gemv_silu_pair_simd`, `llmopt_q8_gemv_add_pair_simd`, `llmopt_q8_gemv_mul_add_pair_simd`), which coalesce memory reads across 128-byte cache lines and use hardware `simd_sum` register shuffles.
   - Decode step latency dropped to **5.92 ms per step** (well below the 10.0 ms Racebench ceiling).
